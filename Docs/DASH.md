# Shift 짧은 대시 — 2026-09-30

사용자 확정: 최대 2연속, 첫 사용 뒤 1초 안에 재입력해야 두 번째를 사용할 수 있으며 쿨타임은 3초다. 구현에서는 **첫 대시 시작부터 1초(경계 포함)**를 연계 입력 시간으로, **마지막 대시 시작부터 3초**를 재사용 대기 시간으로 잡았다.

- 왼쪽/오른쪽 Shift를 누른 순간에 한 번 요청한다. 계속 누르고 있어도 자동 반복하지 않는다.
- A/D 이동 입력이 있으면 그 방향, 없으면 현재 조준/바라보는 방향으로 수평 이동한다.
- 한 번당 0.16초, 초당 15월드 단위, 최대 2.4월드 단위. 맵 끝에서는 멈춘다. `LanRules`에서 조절한다.
- 첫 대시 중 다시 눌러도 두 번째를 한 번 예약해 첫 동작 직후 연결한다. 세 번째 입력과 연계 시간/쿨타임 밖의 입력은 버리고 나중에 자동 실행하지 않는다.
- 공중에서도 사용할 수 있으며 기존 점프 높이·중력은 유지한다.
- 채팅 입력, 장비/파티 창, 게임 포커스가 없는 동안 새 대시 입력을 보내지 않는다.
- 채널 변경은 대시와 예약을 취소하지만 쿨타임은 유지한다.
- 화면 아래에 추가 대시 입력 시간 또는 남은 쿨타임을 표시한다.

## 서버와 표시

`LobbyDash.cs`에서 횟수·방향·시간·좌표를 판정한다. 클라이언트는 대시 속도나 위치를 전송하지 않는다. 틱의 남는 시간을 나누어 처리하므로 0.16초 대시를 0.2초로 올림하지 않는다. 대시 중과 마지막 이동 틱에는 20Hz로 스냅샷을 보내고 평소에는 기존 10Hz를 유지한다.

몸체의 기존 웅크린 자세를 대시에 연결하고, 몸체·양팔·무기의 잔상을 최대 4개 재사용한다. 잔상은 월드 위치에 남았다가 0.14초에 걸쳐 사라지며, 캐릭터가 없어지면 함께 정리한다. 대시 중 위치 보간을 빠르게 해 짧은 이동이 늘어져 보이는 것을 줄였다. 원화 비율과 5방향 무기 조준은 유지한다.

통신 버전은 **5**다. 기존 계정 저장 형식은 그대로이며 서버와 Windows 클라이언트를 모두 갱신했다. 실행 중이던 접속자 없는 개발 서버는 같은 TCP 7777, UDP 7778, 기존 계정 데이터 위치로 갱신 후 재시작했다.

## 검증

- 서버/실제 TLS: **154개 검사 통과**. 연계 시간 안팎과 정확한 1초 경계, 빠른 연속 입력 예약, 세 번째 요청, 3초 쿨타임 경계, 방향 전환, 공중 중력, 맵 경계, 채널 변경, 패킷 재전송, 서로 다른 틱 간격, 두 클라이언트 동기화를 확인했다. `Logs/DashOnlineTests.txt`.
- Unity 리그 **2,520조합 통과**. 대시 자세의 어깨·손잡이·양방향 조준을 추가했다. `Logs/QA/CharacterRigValidation.txt`.
- Windows 빌드 오류 0. 실제 Windows 클라이언트 두 개에서 각각 2회 대시의 이동 거리·낮춘 자세·상대 동기화·세 번째 입력 차단 및 기존 장비/채팅/사격을 확인했다. `Logs/QA/RigClients/`.
- [모션 미리보기](Art/CharacterRedrawV1/ShiftDash.gif)는 Unity의 실제 리그/잔상 렌더러에 2회 대시 타이밍을 재생해 만든 4초 GIF다. 네트워크 녹화가 아니며, 통신 결과는 위 별도 실행 검증을 따른다.

현재 대시 자세는 승인된 몸체 시트의 웅크린 프레임을 활용한다. 별도 대시 도트 원화를 새로 생성한 작업은 아니다.
