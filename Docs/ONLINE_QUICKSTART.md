# 온라인 개발 빌드 실행

**던전 뼈대 제작:** Unity **MiniWar → 던전 제작기 → 방형 예제**에서 방을 배치·드래그 이동하고 원하는 이웃 방만 연결하거나 끊는다. 인접한 방도 통로 없이 둘 수 있다. 새 방과 예제는 방당 기본 8마리이며 보스 방은 보스 1 + 호위 7마리다. 방을 더블클릭하면 바닥·몹·포탈과 도착 위치를 편집한다. 방 클리어 후 전원 집결 이동, 우회 경로, 이전 방 복귀와 몹 재생성 방지를 모의 1~4인으로 테스트한다. 실제 온라인 파티 입장·AI·전투는 후속 작업이다. [제작기 사용법](DUNGEON_BUILDER.md).

**복층 던전:** 같은 제작기의 **복층 예제**를 열면 기존 방 연결 구조에 3층 점프 발판과 층별 몬스터 8마리를 배치한 맵이 나온다. 방을 더블클릭해 편집하거나 **이동 테스트**에서 Space 점프, ↓+Space 하강으로 돌아본다. 현재 던전 제작기 미리보기 기능이며 온라인 마을의 점프 규칙은 바꾸지 않았다.

현재 범위: 계정 등록/로그인, 남녀 선택 저장, 마을 2개 채널(각 30명), 몸체 한 장과 통짜 양팔 한 장의 두 덩이 모션, 이동/점프/2연속 대시/5방향 조준, 마을 연습 사격, 마을 채팅, 지급 무기/재화 저장, 장착 무기 외형 동기화, 4인 파티 모집과 참가 신청 심사. 통신 버전 5로 서버와 클라이언트를 함께 갱신한다.

**Shift 대시:** 첫 사용부터 1초 안에 다시 누르면 최대 2연속. 마지막 대시 시작부터 쿨타임 3초이며 계속 누르고 있어도 자동 반복하지 않는다. 이동 키 방향으로, 이동 키가 없으면 바라보는 방향으로 짧게 이동한다. [세부 규칙과 검증](DASH.md).

파티 준비·던전 입장, 던전/레이드 전투, 보상 카드, 성장, 거래, 랭킹은 아직 이 온라인 빌드에 들어 있지 않다. 혼동을 줄이기 위해 기존 싱글플레이/테스트 씬은 2026-09-28에 제거했다. 재사용할 데이터·전투·성장 코드는 남아 있다.

## 실행
### Unity에서 최신 온라인 씬 열기
Project 창에서 **`Assets/Scenes/OnlineLobby.unity`를 더블클릭**하거나 **MiniWar > Online > Open lobby scene**을 선택한다. 현재 게임 씬과 빌드 시작 씬은 `OnlineLobby` 하나다.

현재 빌드 시작 씬은 `OnlineLobby`다. 에디터의 Play 버튼은 현재 열린 씬을 실행하므로 먼저 온라인 씬을 열어야 한다. 기존 온라인 씬을 여는 데 `Create or refresh lobby scene`으로 다시 생성할 필요는 없다.

예전 `Town`, `Dungeon`, `SampleScene`, `Day2_Aim` 씬과 옛 씬 생성 메뉴는 제거했다. 과거 버전이 필요하면 정리 전 Git 커밋 `ec41fa5`에서 확인할 수 있다. 9월 23일 Notion ZIP은 정리 전 백업이므로 새 작업 폴더에 덮어쓰면 옛 씬이 다시 생긴다.

온라인 마을의 캐릭터·UI는 실행 중에 생성된다. 편집 상태의 Scene 뷰에 보이지 않으면 Game 뷰에서 확인한다. 서버 입력 없이 바로 확인하려면 아래 `PlayMiniWar.cmd`를 사용한다.

### 이 PC에서 바로 플레이 화면 보기
프로젝트 루트의 **`PlayMiniWar.cmd`를 더블클릭**한다. 서버를 직접 켜거나 주소/인증 코드/비밀번호를 입력할 필요 없이 로컬 서버 실행 후 임시 캐릭터로 마을에 자동 입장한다.

- 게임 상단의 **여성으로 보기 / 남성으로 보기**로 캐릭터를 전환한다.
- `A/D` 이동, `W/Space` 점프, `Shift` 대시, 우클릭 조준, 좌클릭 사격, `1/2` 무기 교체, `I` 장비. 마을에서는 탄약 소모·피해 없는 연습탄이다.
- 게임 창을 닫은 뒤 서버까지 종료하려면 **`StopMiniWarServer.cmd`**를 실행한다. 반복 실행하면 이미 켜진 미리보기 서버를 재사용한다.
- 미리보기 서버는 `127.0.0.1:17778`에서만 접속을 받으므로 다른 PC나 방화벽 설정 없이 이 PC에서 확인할 수 있다.
- 별도 저장 위치는 `Builds/LocalPreviewData`. 매번 임시 캐릭터를 생성하며 실제 계정의 로그인 설정이나 기존 서버 저장 파일은 변경하지 않는다.
- 게임 기능 범위는 위에 명시된 공용 마을 개발 빌드와 같다.

### 학원 내부망에서 여러 PC 접속
1. 서버 PC에서 프로젝트 루트의 **`StartMiniWarServer.cmd`**를 더블클릭한다. 게임은 열지 않고 서버만 구동한다. 별도로 옮기려면 `Builds/Server` 폴더 전체를 복사한 뒤 그 안의 **`StartServer.cmd`**를 실행한다. 별도 .NET 설치는 필요 없다.
2. 서버 창을 켜 둔다. 주소나 인증 코드를 참가자에게 전달할 필요가 없다.
3. 참가자는 `Builds/OnlineClient/MiniWar.exe` 실행. 이쪽도 폴더 전체가 필요하다.
4. 게임이 같은 내부망의 서버를 자동 검색한다. 화면에는 **접속가능 / 접속불가**와 **새로고침**만 표시한다. 서버 이름과 기술 설명은 표시하지 않는다. 게임을 먼저 켜도 서버가 실행되면 다음 검색에서 발견한다. 처음 검색할 때 서버가 여러 개면 임의로 계정을 보내지 않고 미선택 상태로 유지하므로, 사용할 서버 하나만 켜 둔다.
5. 닉네임과 비밀번호를 입력하고 남성/여성을 선택해 **새 계정 등록**. 현재는 계정당 캐릭터 1명이다. 이후에는 **접속**을 사용한다. 로그인 화면의 남녀 선택은 새 계정 생성에만 적용된다.
6. 같은 채널에서 만나고 마을 채팅을 이용한다. `A/D` 이동, `W/Space` 점프, 우클릭 조준, `I` 장비, `1/2` 지급 권총/근접무기 교체.

학원 내부망에서 서버의 **TCP 7777(게임), UDP 7778(자동 검색)** 통신이 허용되어야 한다. 다른 서브넷 또는 무선 클라이언트 격리 환경에서는 자동 검색이 되지 않을 수 있다. 현재 자동 방화벽 변경은 수행하지 않았다.

서버 구동기 창에는 점검용 IPv4 주소, 포트, 저장 위치와 자동 검색 상태가 표시된다. 일반 게임은 `Builds/OnlineClient/MiniWar.exe`로 별도로 연다. **서버 창에서 Ctrl+C**를 누르면 종료된다. 이미 사용 중인 포트에는 중복 실행하지 않으며 기존 프로세스를 강제로 끄지 않는다. 한 PC에서는 자동 검색 포트 7778을 사용하는 LAN 서버 하나만 실행한다. 계정은 `%LOCALAPPDATA%/MiniWar/Server`에 유지된다. `PlayMiniWar.cmd`와 `StopMiniWarServer.cmd`는 별도의 로컬 미리보기용이며, 이 LAN 서버의 실행·종료와 구분한다. 로컬 미리보기 서버는 일반 서버 검색 목록에 표시하지 않는다.

## 파티 만들기와 참가하기
1. 같은 마을 채널에서 **P** 또는 오른쪽 위 **파티 [P]** 버튼을 누른다.
2. 파티장은 2~24자 이름을 입력하고 **새 파티 만들기**를 누른다.
3. 다른 사람은 목록의 **참가 신청**을 누른다. 한 번에 한 파티에만 신청 가능하며 **신청 취소** 후 다른 파티로 바꿀 수 있다.
4. 파티장은 **참가 신청** 영역에서 **수락 / 거절**한다. 수락하면 양쪽의 파티원 목록이 갱신되고, 거절하면 신청자에게 알림이 간다.
5. 파티는 최대 4명이다. 가득 차면 나머지 신청은 자동 종료된다. **파티 탈퇴**로 나갈 수 있으며 마지막 인원의 버튼은 **파티 해산**이다.
6. 파티장이 나가거나 연결이 종료되면 먼저 가입한 동료에게 승계된다. 파티원은 탈퇴 후 채널을 옮긴다. 가입 전 채널 이동은 대기 신청을 취소한다.

파티 창을 연 동안 캐릭터 이동·점프·조준·사격·단축키 장비 교체를 멈춘다. `Esc` 또는 **닫기**로 돌아간다. 파티 이름 입력 중 `P`는 문자로 입력된다. 아직 던전 입장 버튼은 없다.

## 저장과 서버 인증
- 기본 저장 폴더: `%LOCALAPPDATA%/MiniWar/Server`.
- `accounts.json`: 비밀번호의 PBKDF2 해시와 salt, 닉네임, 캐릭터 외형, 개별 무기 ID, 장착 무기, 재화.
- `accounts.json.backup`: 직전 저장본. 서버를 종료한 뒤 저장 폴더 전체를 백업한다.
- `server.pfx`: 서버 인증서와 개인 키. 배포하지 않는다.
- `server-fingerprint.txt`: 내부 TLS 연결 확인용 지문. 사용자에게 입력받지 않으며 검색 응답으로 자동 전달한다.
- 서버 인증서를 바꾸면 **새로고침** 후 재접속한다. TLS 암호화와 발견한 서버의 지문 일치 검사는 유지하지만, 검색 응답 자체는 같은 내부망을 신뢰한다. 수동 코드 대조를 통한 서버 운영자 신원 확인은 하지 않는다.
- 데이터가 손상되었을 때 계정을 자동 초기화하지 않고 오류로 종료한다.
- 테스트는 `Tools/McpSetup/SmokeData`, 포트 `17777`을 사용하며 실제 기본 저장 폴더와 분리되어 있다.

## 다시 빌드
- 서버: PowerShell에서 `./Tools/Build-Server.ps1`.
- 클라이언트: Unity 메뉴 `MiniWar > Online > Build Windows client`.
- 온라인 씬 생성/갱신: `MiniWar > Online > Create or refresh lobby scene`. 현재 열린 씬에 저장하지 않은 변경이 있으면 먼저 저장해야 한다.
- 서버 검증: .NET 10 SDK로 `dotnet run --project Tests/Online/MiniWar.Online.Tests.csproj`.
- Windows 실행 파일 검증용 `--miniwar-smoke-config`는 Development Build에서만 존재하는 명시적 테스트 진입점이다. 보통 실행에서는 작동하지 않는다.

## 아트
`Assets/Resources/Online/`에 마을 배경, 남녀 몸체, 별도 무기 아틀라스가 있다. 각 무기의 종류/등급으로 그림을 고른다. **피스톨과 리볼버는 별개이며 각각 1~3등급 외형을 가진다.** 등급 상승으로 피스톨이 리볼버로 바뀌지 않는다. 시작 지급은 피스톨과 근접무기이며 나머지 무기를 얻는 상점/보상 흐름은 후속 작업이다. `Handguns.png`는 왼쪽 열 피스톨, 오른쪽 열 리볼버이다. 클라이언트와 서버 모두 통신 버전 5 빌드를 사용해야 한다.

현재 월드 캐릭터는 연결된 몸체 한 장 + 양팔 한 장 + 별도 총을 사용한다. 남녀 대기·걷기·점프·5방향 팔과 장비는 `Assets/Resources/Online/PixelV1/`의 도트 원화로 교체했다. 여캐는 원래 참고의 얼굴·체형을 복원하고 도트 표현을 유지했다. 팔꿈치/손목 IK는 사용하지 않는다. 5방향 자세와 실제 발사각은 별도이며 탄은 발사 후 직진한다. Unity 메뉴 **MiniWar > Characters > Motion preview**에서 확인한다. **Pixel style study**는 과거 남캐 대기 한 자세의 기준 샘플이다. 로그인 초상화는 기존 그림이며, 걷기의 발 구분/의상 연속성 다듬기·던전 피해 판정·재장전·피격 모션은 후속 작업이다. 상세 규칙은 `Docs/CHARACTER_ANIMATION.md`, 원화/프롬프트 기록은 `Docs/Art/PixelMotionV1.md` 참고.
