# 온라인 개발 빌드 실행

현재 범위: 계정 등록/로그인, 남녀 선택 저장, 마을 2개 채널(각 30명), 이동/점프/조준 방향, 마을 채팅, 지급 무기/재화 저장, 장착 무기 외형 동기화.

파티, 던전/레이드 전투, 보상 카드, 성장, 거래, 랭킹은 아직 이 온라인 빌드에 들어 있지 않다. 기존 싱글플레이 씬은 유지되어 있지만 온라인 흐름과 연결하지 않았다.

## 실행
### 이 PC에서 바로 플레이 화면 보기
프로젝트 루트의 **`PlayMiniWar.cmd`를 더블클릭**한다. 서버를 직접 켜거나 주소/인증 코드/비밀번호를 입력할 필요 없이 로컬 서버 실행 후 임시 캐릭터로 마을에 자동 입장한다.

- 게임 상단의 **여성으로 보기 / 남성으로 보기**로 캐릭터를 전환한다.
- `A/D` 이동, `W/Space` 점프, 우클릭 조준, `1/2` 무기 교체, `I` 장비.
- 게임 창을 닫은 뒤 서버까지 종료하려면 **`StopMiniWarServer.cmd`**를 실행한다. 반복 실행하면 이미 켜진 미리보기 서버를 재사용한다.
- 미리보기 서버는 `127.0.0.1:17778`에서만 접속을 받으므로 다른 PC나 방화벽 설정 없이 이 PC에서 확인할 수 있다.
- 별도 저장 위치는 `Builds/LocalPreviewData`. 매번 임시 캐릭터를 생성하며 실제 계정의 로그인 설정이나 기존 서버 저장 파일은 변경하지 않는다.
- 게임 기능 범위는 위에 명시된 공용 마을 개발 빌드와 같다.

### 학원 내부망에서 여러 PC 접속
1. 서버 PC에서 `Builds/Server/MiniWar.Server.exe` 실행. 폴더 전체를 복사해야 한다. 별도 .NET 설치는 필요 없다.
2. 서버 창에 표시되는 SHA-256 인증 코드를 참가자에게 전달한다.
3. 참가자는 `Builds/OnlineClient/MiniWar.exe` 실행. 이쪽도 폴더 전체가 필요하다.
4. 서버 주소는 서버 PC의 학원 내부 IPv4 주소, 포트는 `7777`. 같은 PC에서 시험하면 `127.0.0.1`.
5. 인증 코드, 닉네임, 비밀번호를 입력하고 남성/여성을 선택해 **새 계정 등록**. 현재는 계정당 캐릭터 1명이다. 이후에는 **접속**을 사용한다. 로그인 화면의 남녀 선택은 새 계정 생성에만 적용된다.
6. 같은 채널에서 만나고 마을 채팅을 이용한다. `A/D` 이동, `W/Space` 점프, 우클릭 조준, `I` 장비, `1/2` 지급 권총/근접무기 교체.

학원 PC에서 Windows 방화벽이 물으면 학원 내부망에서 서버의 TCP 7777 통신을 허용해야 한다. 외부 인터넷 포트포워딩은 하지 않는다. 현재 자동 방화벽 변경은 수행하지 않았다.

## 저장과 서버 인증
- 기본 저장 폴더: `%LOCALAPPDATA%/MiniWar/Server`.
- `accounts.json`: 비밀번호의 PBKDF2 해시와 salt, 닉네임, 캐릭터 외형, 개별 무기 ID, 장착 무기, 재화.
- `accounts.json.backup`: 직전 저장본. 서버를 종료한 뒤 저장 폴더 전체를 백업한다.
- `server.pfx`: 서버 인증서와 개인 키. 배포하지 않는다.
- `server-fingerprint.txt`: 참가자에게 전달할 공개 인증 코드.
- 서버 인증서를 지우면 인증 코드도 변경된다. 기존 플레이어가 저장한 코드와 맞지 않으면 접속이 거절된다.
- 데이터가 손상되었을 때 계정을 자동 초기화하지 않고 오류로 종료한다.
- 테스트는 `Tools/McpSetup/SmokeData`, 포트 `17777`을 사용하며 실제 기본 저장 폴더와 분리되어 있다.

## 다시 빌드
- 서버: PowerShell에서 `./Tools/Build-Server.ps1`.
- 클라이언트: Unity 메뉴 `MiniWar > Online > Build Windows client`.
- 온라인 씬 생성/갱신: `MiniWar > Online > Create or refresh lobby scene`. 현재 열린 씬에 저장하지 않은 변경이 있으면 먼저 저장해야 한다.
- 서버 검증: .NET 10 SDK로 `dotnet run --project Tests/Online/MiniWar.Online.Tests.csproj`.
- Windows 실행 파일 검증용 `--miniwar-smoke-config`는 Development Build에서만 존재하는 명시적 테스트 진입점이다. 보통 실행에서는 작동하지 않는다.

## 아트
`Assets/Resources/Online/`에 마을 배경, 남녀 몸체, 별도 무기 아틀라스가 있다. 각 무기의 종류/등급으로 그림을 고른다. **피스톨과 리볼버는 별개이며 각각 1~3등급 외형을 가진다.** 등급 상승으로 피스톨이 리볼버로 바뀌지 않는다. 시작 지급은 피스톨과 근접무기이며 나머지 무기를 얻는 상점/보상 흐름은 후속 작업이다. `Handguns.png`는 왼쪽 열 피스톨, 오른쪽 열 리볼버이다. 클라이언트와 서버 모두 통신 버전 2 빌드를 사용해야 한다.

현재 몸체는 대기/권총 준비 자세 시트이다. 보행, 점프, 재장전, 피격, 발사 애니메이션과 손목 조준 연동은 추가 제작이 필요하다. 원본 NPC 그림은 그대로 사용했다.

## 검증 범위
- 2026-09-23: 자동 검증 52개 통과. 피스톨/리볼버 각각 3등급 저장, 장착 유지, 원격 외형 구분을 포함한다.
- Unity에서 총기 6종과 근접무기의 3등급 스프라이트 총 21개 로딩을 확인했고, 모든 등급에서 피스톨/리볼버가 서로 다른 열을 참조하는 것을 검증했다.
- Windows 실행 파일 2개 동시 실행: 남녀 각각 등록/접속, 장착 교체, 한글 채팅 전달, 두 캐릭터와 별도 무기 스프라이트 로딩 통과. 결과는 `Logs/QA/Windows-Male-result.txt`, `Logs/QA/Windows-Female-result.txt`.
- Unity 에디터 실제 서버 접속과 여성 권총 준비 자세 화면 확인. 현재 스크린샷은 `Logs/QA/OnlineFemale.png`.
- 자동화: 실제 TLS 클라이언트 2개, 계정/비밀번호/장비 저장, 재시작 복원, 소유권 거절, 남녀/장비/조준 외형 동기화, 한글 채팅, 채널 이동.
- 서버 월드 모형: 60명 슬롯과 채널별 30명 제한. 실제 학원 PC 30대 부하 검증과 같지 않다.
- 학원 PC 간 LAN 실기 확인은 별도로 필요하다.
