# MiniWar — 왕국 탈환전

2026-09-23 사용자와 확정한 최신 기획. 초기 Notion 기획/Assets/Scripts/README.md보다 우선한다.

## 목표
- 최신 접속 결정 (2026-09-30): 서버 주소·인증 코드 수동 입력 없이 UDP 7778로 내부망 서버를 자동 발견한다. 닉네임·비밀번호만 입력하며 UI에는 접속가능/접속불가와 새로고침만 표시한다. 여러 서버가 처음 발견되면 임의로 선택하지 않는다. TLS 암호화는 유지하고 지문은 검색 응답으로 받아 사용한다. 검색망을 신뢰하므로 수동 인증 코드 대조와 같은 운영자 신원 보장은 하지 않는다.
- 1인 학원 프로젝트, 약 3~4일 제작 목표. Windows 클라이언트, 학원 내부 LAN.
- 학원 Windows PC에서 서버를 직접 실행한다.
- 닉네임/비밀번호로 계정 등록·로그인. 계정마다 진행·재화·개별 무기를 영구 저장한다.
- 마을 약 20~30명. 필요시 채널 분리. 마을 채팅과 파티 채팅.
- 파티 일반 던전 4개, 레이드 1개, 마을 1:1 거래, 레이드 클리어 시간 랭킹.

## 세계관과 아트
총기를 사용하는 주인공 왕국을 마법 왕국이 흑마법으로 침공했다. 주인공들은 점령당한 고향을 탈환한다. 아라곤은 점령군의 왕이다. 마을은 생존자와 탈환군의 준비 거점이다.

던파풍 판타지 도트. 기존 NPC 스프라이트는 보존하며 나머지 배경·주인공·적·UI는 개편한다. 좌우 이동·점프·마우스 조준과 총기·근접무기를 사용한다.

대시 확정(2026-09-30): Shift로 짧은 수평 대시. 첫 사용 뒤 1초 안에 재입력하면 한 번 더 사용할 수 있다(최대 2회). 마지막 대시 시작부터 재사용 대기 3초. 이동 키 우선, 없으면 바라보는 방향. 서버가 시간·횟수·좌표를 판정한다. [구현 기록](DASH.md).

### 캐릭터·총기 최신 결정
- 생성 시 남성/여성 선택. 선택한 외형은 계정에 저장하고 다른 플레이어에게 동기화한다.
- 남성: 생성된 갈색 머리·남색 코트 디자인 유지. 여성: 첨부한 금발·검은 베레모·검은 군복·금색 장식·흰 장갑 디자인 참고.
- 총기는 **샷건 / 소총 / 기관단총 / 저격총 / 피스톨 / 리볼버** 6종이다. 권총 안에서 글록 같은 피스톨과 회전 탄창의 리볼버를 독립된 종류로 구분한다. 미사일 제외. 탄약 없이 쓰는 근접무기는 별도 계열이다.
- 피스톨과 리볼버는 각각 1~3등급을 가지며, 등급 상승으로 종류가 바뀌지 않는다. 두 종류 모두 얼굴 옆으로 세워 드는 권총 준비 자세를 쓴다. 공격력·연사·장탄수 차이는 아직 미정이다.
- 프로토콜 ID: 피스톨=0, 기관단총=1, 샷건=2, 소총=3, 저격총=4, 근접=5, 리볼버=6. 기존 저장 ID는 유지한다. 통신 버전은 5이며 클라이언트와 서버를 함께 갱신한다. 이전 Claude 초안의 대전차/수류탄 ID와 혼용 금지.
- 몸과 총기 스프라이트를 분리한다. 장착한 개별 무기의 계열·등급에 맞는 실제 무기를 표시한다.
- 권총 대기 자세: 사용자의 스케치처럼 팔꿈치를 굽혀 총을 얼굴 옆으로 세운다.
- 조준 자세 확정(2026-09-28): **위 +90° / 윗사선 +45° / 앞 0° / 아랫사선 -45° / 아래 -90°**. 몸이 바라보는 쪽을 정면으로 삼고 왼쪽은 좌우 반전한다. 에임과 가장 가까운 자세를 택한다(경계 ±22.5°, ±67.5°).
- 탄도 확정: 발사 순간 실제 에임 방향으로 보정한 뒤 직진한다. 발사 후 커서를 따라 휘어지거나 적을 자동 추적하지 않는다. 자세와 발사각의 차이는 최대 22.5°다. 산탄은 이 발사각을 중심으로 무기별 퍼짐을 적용한다. 실제 총구에서 에임 지점까지의 방향과 명중은 전투 구현 때 서버가 판정한다.
- 애니메이션 구현: 남녀 각각 연결된 몸체 한 장 + 양팔 한 장으로 표시한다. 프레임별 어깨 좌표에 통짜 팔을 붙이고 5방향 자세를 교체한다. 무기는 별도이고 팔꿈치 IK는 사용하지 않는다. 남녀 대기·걷기·점프와 12개 양팔 자세, 21개 장비 외형을 새 도트 원화로 연결했다. 몸체는 14개 그림을 16칸에 등록한다(대기 2장 반복). 여캐는 사용자 참고의 얼굴·체형을 유지하면서 도트 표현을 살린다. 현재 에셋은 `Assets/Resources/Online/PixelV1/`. 걷기의 발 구분/의상 연속성 다듬기는 남아 있다.
- 현재 온라인 사격은 탄약 소모·피해 없는 마을 연습탄이다. 서버가 장착 무기·연사 간격·입력 순번을 검증하고 같은 채널에 발사각을 전송한다. 탄은 실제 에임 방향으로 직진하며 샷건만 대칭 퍼짐을 적용한다. 전투용 서버 총구/충돌/피해, 재장전·피격 모션은 후속 작업이다. 세부 사용법은 `Docs/CHARACTER_ANIMATION.md`.

## 파티 모집 (2026-09-30 구현)

### UI 외형 (2026-09-30)
사용자가 첨부한 구 엘소드 화면을 참고해 불투명한 밝은 회색 패널, 둥근 모서리, 청록색 제목줄과 입체 버튼을 적용했다. 파티·장비·로그인 창, 마을 상단바·채팅이 같은 테마를 공유한다. `OnlineUiSkin.cs`에서 작은 9-slice 텍스처를 한 번 생성해 재사용하며 원본 게임의 이미지 자산을 복사하지 않는다. 기능과 파티 규칙은 유지한다. 화면 기록: `Logs/QA/PartyRecruitment-1.png`, `Logs/QA/RetroInventory.png`.

### 모집 규칙
- 파티장이 이름을 정해 생성 → 같은 마을 채널의 파티 목록 → 참가 신청 → 파티장이 수락 또는 거절한다. 초대 방식에서 사용자 요청의 신청 방식으로 변경했다.
- 현재 일반 파티는 파티장 포함 최대 4명. 한 번에 한 파티에만 신청할 수 있고, 수락 전에는 파티원이 아니다.
- 신청 취소·재신청·파티 탈퇴 가능. 정원에 도달하면 남은 신청은 사유 알림과 함께 종료한다.
- 파티장이 탈퇴하거나 연결이 종료되면 먼저 참가한 남은 파티원이 승계한다. 마지막 인원이 나가면 해산하고 대기 신청도 종료한다.
- 파티원은 탈퇴 후 채널 이동. 가입 전 신청자는 채널 이동 시 신청을 자동 취소한다.
- 파티와 신청은 서버 메모리에만 유지하며 재접속 때 자동 복구하지 않는다. 캐릭터·장비·재화 저장과 별개다.
- 서버가 권한·정원·채널·가입 여부와 개별 신청 ID를 검사한다. 신청자 목록은 해당 파티장에게만 전송한다.
- `P` 또는 오른쪽 위 **파티 [P]** 버튼으로 목록/파티원/신청함을 연다. 준비 상태, 파티 채팅, 던전 입장, 레이드 6인 모집은 후속 작업이다.

## 전투 규칙
- 일반 던전 1~4명. 입장 인원별 개인 공격력: 4명 ×1, 3명 ×1.25, 2명 ×1.8, 1명 ×3.3.
- 레이드 4~6명. 인원 공격력 보너스 없음.
- 공격력 보너스는 입장 인원으로 고정한다(제안 기본안).
- 개인당 인던 1회에 한 번 제자리 부활, 체력 100%, 짧은 무적. 두 번째 사망 이후 팀원 관전.
- 전원 최종 사망 시 실패 후 마을 귀환.
- 탄약·재화 부족은 강제 탈락이 아니다. 근접무기로 계속 싸울 수 있어야 한다.
- 큰 범위기는 화면 경고와 바닥 전조. 즉사기는 패턴 파훼로 중단 가능하며 솔로 일반 던전에서도 파훼 가능해야 한다.

## 보상·거래·성장
- Claude outputs의 성장 설계를 서버 판정으로 이식하되 무기 분류는 최신 결정을 따른다: 총기 6종과 별도 근접무기, 각각 3등급, 개별 인스턴스, +15 확률 강화, 하락/파괴, 3정 합성, 분해/부적/방지권.
- 일반 공용 카드 4장, 레이드 공용 카드 8장. 모두 같은 화면을 보고 각자 서로 다른 카드 한 장을 선택한다.
- 보상은 서버가 미리 결정하고 선택 완료 시 한 번만 지급한다. 미선택 보상은 공개하지 않는다.
- 남은 카드는 선택 종료 후 불타 사라지는 연출.
- 시간 초과·접속 종료 시 자동 배정/지급은 기본 제안이며 별도 사용자 변경이 없으면 적용한다.
- 무기와 재화는 영구 보유, 멀티에서 사용 가능. 강화 무기도 1:1 거래 가능. 경매장 제외.
- 마을에서 양측이 물품을 확인하고 최종 승인한다. 제안 변경 시 양측 승인을 초기화한다.
- 서버가 전투 시작부터 보스 사망까지 측정해 레이드 참여자 전원 이름과 시간을 저장한다.

## 구현 원칙
서버가 이동 한계·공격·피해·재화·아이템·강화·카드 지급·거래·랭킹을 검증한다. 클라이언트가 보상/수치를 확정하지 않는다. 거래 양측 저장은 하나의 트랜잭션이어야 한다. 비밀번호 평문 저장 금지.
